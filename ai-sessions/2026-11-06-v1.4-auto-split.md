## 需求

1. 版本号升级到 v1.4；启动时把版本号写入日志。
2. 启动时把当前选项也写日志（Teams 监控 / 开机启动 / 语言，本次追加自动分割）。
3. 确认「设备变化」已有日志（已有：`Audio device changed`）。
4. 新增「自动分割」语音文件：复选框（默认不勾选）+ 下拉框 15/30/60/90 分钟；分割出的文件在原文件名后加 `_1`、`_2` …
5. 讨论「接入 AI 做转写 + Summary」的技术方案（本次只讨论，未动代码）。

## 决策

- 分段命名：第一段保留原文件名，之后依次 `_1`、`_2`（用户原话「自动分割的语音命名后面加上_1, _2」）。
- 分割不重启采集线程，避免录音出现间隙/设备重开失败：给编码器加一层「槽位」间接寻址，切换时先开新文件、加锁原子替换、再关闭旧文件。
- 打开新分段失败时的降级策略：本次录制放弃分割（继续写原文件），不中断录音；日志记录失败原因。不改动用户保存的设置。
- 分割检查挂在已有的 2s 看门狗定时器（`TIMER_WATCH`）上，独立于 Teams 监控开关；边界误差 ≤ 2s，对 15 分钟级分割可忽略。
- 「已录」计数不随分段增加（仍按录制场次计）。
- 录制中禁用「自动分割」复选框与下拉框（与 AEC 一致）。
- 时长默认 30 分钟；配置 key：`[Options] auto_split=0/1`、`split_minutes=15|30|60|90`。

## 踩坑 / 注意

- 用 Edit 工具改 ini 会破坏 UTF-16LE：语言文件必须走 PowerShell `[System.IO.File]::WriteAllText(..., Encoding.Unicode)`（含 FFFE BOM、CRLF）。本次用临时 ps1 脚本（UTF-8 保存）插入中文 key，已验证 BOM 与中文正确。
- Rust `WM_COMMAND` 只取 `LOWORD(wp)`：下拉框的 `CBN_SELCHANGE` 也会带同一个 id，必须判 `HIWORD(wp)`，否则误触发。
- 把 `mixer->Open` 的回调从「裸指针」改成「查全局」后，必须先给 `g_writer` 赋值再 `capture->Begin()`，否则开头几毫秒会被丢弃。
- `PathBuf::with_extension` 消耗 self，需要 `clone()` 才能保留 base 供分段用。

## 第三轮：自动录制失败的处理与自愈（同日，用户批准 P0/P3/P4）

用户问「自动录制出现录制失败时如何解决？能否刷新设备找出正在使用的设备」。诊断出的 4 个真实缺陷：

1. 自动开始失败 → `g_autoSuppress = true`，整场会议不再重试。
2. 录制中途设备掉线 → `WM_RECORD_ERROR` → `StopRecording()` 里的 `if (g_autoStarted && 会议仍活跃) g_autoSuppress = true` —— 异常中断与用户手动停止无法区分，结果同样整场不再自动重开（**最主要的坑**）。
3. 自动开始录的是 UI 下拉框设备，不是会议实际所在设备 → 录错设备/录到静音。
4. 录制中设备变化不刷新，也没有任何重连。

已实现（两版一致）：

| 层 | 做法 | 位置 |
|----|------|------|
| P0 停止原因 | `enum class StopReason{User,DeviceError,Auto,Exiting}` / Rust `enum StopReason`。只有 `User` 置 auto-suppress；`DeviceError` 置 `retryCountdown=1`（2s 后看门狗重开）。调用点：按钮=`User`、`WM_RECORD_ERROR`=`DeviceError`、`WM_CLOSE`=`Exiting`、会议结束自动停=`Auto` | `recorder.{h,cpp}`, `main.cpp`, `app.rs` |
| P1 正在使用的设备 | `MeetingActive(app, deviceId, deviceName)`：命中 `AudioSessionStateActive` + 会议 PID 的那个端点即会议输出所在设备，返回其 `GetId` + `PKEY_Device_FriendlyName`；保留只传 app 的重载以免改动无关调用点 | `teams_watcher.{h,cpp}`, `teams_watcher.rs` |
| P2 失败重试 | `RefreshDevicesKeepingSelection()`（刷新但保留用户选择，录制中还会把被放开的控件重新禁用）→ 用 P1 设备重试，退避 `kRetryTicks {1,2,4}` tick（2/4/8s），第 4 次失败才 gave up | 同上 |
| P3 掉线自愈 | `TryReconnectCapture()`：先 `Stop()` 采集但**不**关编码器 → 刷新设备 → 新端点起 `WasapiCapture` → 开新的 `..._N.mp3`（复用分割命名）→ 关旧编码器（旧内容落盘）→ 新 mixer + `Begin()`。失败才回落 `StopRecording(DeviceError)`。Rust `try_reconnect_capture()` 用 `WriterSlot::replace` | `recorder.cpp`, `app.rs` |
| P4 麦克风降级 | 麦克风起不来不再让整场失败：日志 + 继续只录播放设备；手动模式弹 `MB_ICONWARNING`（新 key `warn_mic_fallback`），自动模式只写状态栏/日志 | 同上 |

新增语言 key（两个 ini 都加，插在 `[Status] auto_teams_on=` 之后）：`warn_mic_fallback`、`auto_reconnecting`。
新增 `ResetAutoWatchState()`（打开自动录制开关时清 suppress/polls/retries）。

注意点 / 坑：

- Rust `render_ids` 里的设备 ID **含结尾 NUL**（`wide_string_from_ptr` 复制 `len+1`），所以 `teams_watcher.rs` 里必须用同样含 NUL 的复制方式，否则与 `render_ids` 比较永远不相等。
- C++ `StopRecording` 里读 `g_pendingError` 判定「中断」；重连成功必须清 `g_pendingError`，否则下一次正常停止会带着旧错误文案被记成 interrupted。
- 重连时 `RefreshDevices()` 会 `EnableWindow(btnStart, TRUE)` 并把下拉框选择重置为默认设备 → 必须走 `RefreshDevicesKeepingSelection()`，录制中还要把控件重新禁用。
- 采集线程的错误路径是「循环退出后才调用 `m_errorFn`」，所以 UI 线程里 `Stop()` join 不会死锁。
- 顺带修：Rust `WM_RECORD_ERROR` 的状态栏硬编码中文（违反「不得硬编码文案」规则）改为 `tr("Status","end"/"interrupted")`；看门狗日志文案两版对齐。

验证状态：两版编译通过（C++ Release 无 warning，Rust release 无 warning）；空目录跑 10s（`auto_teams=1 auto_split=1 split_minutes=15`）无崩溃，本机无会议进程所以自动路径未触发。**P1/P2/P3/P4 需要真机场景**：拔掉/切换播放设备、麦克风被占用或拔出、会议中设备消失。已列入 `progress.md` 高优先级验证项。
