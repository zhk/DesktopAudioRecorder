## 需求

1. 版本号升级到 v1.4；启动时把版本号写入日志。

5. 讨论「接入 AI 做转写 + Summary」的技术方案（本次只讨论，未动代码）。

## 决策

- 分段命名：第一段保留原文件名，之后依次 `_1`、`_2`（用户原话「自动分割的语音命名后面加上_1, _2」）。
- 分割不重启采集线程，避免录音出现间隙/设备重开失败：给编码器加一层「槽位」间接寻址，切换时先开新文件、加锁原子替换、再关闭旧文件。
- 打开新分段失败时的降级策略：本次录制放弃分割（继续写原文件），不中断录音；日志记录失败原因。不改动用户保存的设置。
- 分割检查挂在已有的 2s 看门狗定时器（`TIMER_WATCH`）上，独立于 Teams 监控开关；边界误差 ≤ 2s，对 15 分钟级分割可忽略。
- 「已录」计数不随分段增加（仍按录制场次计）。
- 录制中禁用「自动分割」复选框与下拉框（与 AEC 一致）。
- 时长默认 30 分钟；配置 key：`[Options] auto_split=0/1`、`split_minutes=15|30|60|90`。

## 踩坑 / 注意

- 用 Edit 工具改 ini 会破坏 UTF-16LE：语言文件必须走 PowerShell `[System.IO.File]::WriteAllText(..., Encoding.Unicode)`（含 FFFE BOM、CRLF）。本次用临时 ps1 脚本（UTF-8 保存）插入中文 key，已验证 BOM 与中文正确。
- Rust `WM_COMMAND` 只取 `LOWORD(wp)`：下拉框的 `CBN_SELCHANGE` 也会带同一个 id，必须判 `HIWORD(wp)`，否则误触发。
- 把 `mixer->Open` 的回调从「裸指针」改成「查全局」后，必须先给 `g_writer` 赋值再 `capture->Begin()`，否则开头几毫秒会被丢弃。
- `PathBuf::with_extension` 消耗 self，需要 `clone()` 才能保留 base 供分段用。

## 顺手发现的既有缺陷（未修，等确认）

1. C++ 版录制期间状态框不刷新：`TIMER_ID` 从未 `SetTimer`（Rust 版在 `start_recording` 里设了 500ms）。
2. Rust 版语言切换实际无效：`LOCALE`/`STRINGS` 是 `OnceLock`，第二次 `set()` 静默失败，界面仍是旧语言。
3. Rust 版日志文案与 C++ 不一致（`Teams monitor ON/OFF` vs C++ `Meeting monitor ON/OFF`）。
4. C++ 语言切换重建控件时，`EnableWindow` 只禁用了两个下拉框（Rust 版完全没禁用），录制中切语言会短暂放开设备选择。
